# 지침: 자동 기능 개발 (develop_feature)

이 지침은 에이전트가 사용자의 요구사항을 받아 자율적으로 기능을 개발하는 과정을 정의합니다.

## 목표
사용자가 요청한 기능을 최소한의 질문으로 자동 구현하고, 코드 품질과 테스트를 보장합니다.

## 입력 항목
- `feature_description`: 사용자가 요청한 기능 설명 (자연어)
- `project_name`: 대상 프로젝트 (기본값: prayer-agent)
- `priority`: 우선순위 (high/medium/low, 기본값: medium)

## 에이전트 자율 행동 원칙

### 1. 질문 최소화
- **하지 말 것**: 모호한 질문 ("어떻게 하시겠어요?", "괜찮나요?")
- **할 것**: 합리적인 기본값으로 자동 진행
- **예외**: 중대한 결정만 확인 (데이터 삭제, 외부 API 비용 발생 등)

### 2. 컨텍스트 우선 탐색
기능 구현 전 반드시:
1. 프로젝트 구조 파악 (Glob, Grep)
2. 유사 코드 패턴 찾기
3. 기존 스타일 및 컨벤션 따르기

### 3. 점진적 구현
```
1. 핵심 기능 구현 → 2. 로컬 테스트 → 3. 에러 수정 → 4. 문서화 → 5. 커밋
```

### 4. 자동 의사결정 가이드

| 상황 | 결정 |
|------|------|
| 파일 위치 모호 | 기존 패턴 따름 |
| 라이브러리 선택 | 프로젝트에 이미 있는 것 우선 |
| 스타일 불명확 | ESLint/Prettier 설정 따름 |
| API 디자인 | RESTful 원칙 적용 |
| 에러 처리 | 항상 포함 (fallback + 로깅) |
| 테스트 필요성 | 항상 작성 (단위 테스트 최소) |

## 실행 단계

### Phase 1: 분석 (자동)
```bash
# 프로젝트 구조 파악
glob "projects/{project_name}/**/*.{js,jsx,py}"

# 관련 코드 검색
grep -r "similar_functionality" projects/{project_name}/
```

### Phase 2: 계획 (자동)
- 필요한 파일 목록 생성
- 영향받는 컴포넌트 식별
- 의존성 확인

### Phase 3: 구현 (자동)
- 코드 작성 (기존 패턴 따름)
- 에러 처리 추가
- 로깅 추가

### Phase 4: 검증 (자동)
```bash
# 실행 스크립트 호출
python execution/run_tests.py {project_name}
```

### Phase 5: 문서화 (자동)
- 코드 주석 (필요한 경우만)
- README 업데이트 (주요 기능인 경우)
- Directive 학습 내용 추가

### Phase 6: 커밋 (자동)
```bash
git add <files>
git commit -m "feat: <feature_description>

Co-Authored-By: Claude Sonnet 4.5 <noreply@anthropic.com>"
```

## 에러 발생 시 자동 처리 (Self-Annealing)

1. 에러 로그 분석
2. 원인 파악 (스택 트레이스, API 문서)
3. 수정 시도 (최대 3회)
4. 수정 불가 시: 사용자에게 명확한 상황 보고

## 사용자 개입이 필요한 경우

**오직 다음 경우에만 질문:**
1. 외부 비용 발생 (유료 API 호출, 서버 생성 등)
2. 데이터 손실 위험 (DB 삭제, 마이그레이션)
3. 보안 설정 (API 키, 인증)
4. 완전히 새로운 아키텍처 선택

**질문 형식:**
- 명확한 선택지 (2-3개)
- 각 선택의 영향 설명
- 추천 옵션 표시

## 출력 형식

### 성공 시
```
✅ 기능 구현 완료: {feature_description}

변경 사항:
- {file_path_1}: {요약}
- {file_path_2}: {요약}

테스트: {통과/실패}
커밋: {commit_hash}
```

### 실패 시
```
❌ 구현 실패: {feature_description}

시도 내역:
1. {시도1} → {결과}
2. {시도2} → {결과}

필요한 사용자 입력:
- {구체적 요청}
```

## 품질 기준

모든 코드는:
- [ ] 기존 패턴 준수
- [ ] 에러 처리 포함
- [ ] 로컬 테스트 통과
- [ ] 보안 취약점 없음 (XSS, SQL Injection 등)
- [ ] 성능 고려 (불필요한 연산 제거)
